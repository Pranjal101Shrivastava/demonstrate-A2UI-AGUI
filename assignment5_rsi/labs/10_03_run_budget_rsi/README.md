# 10.03 · Run Budget RSI: score edits before running them

[Course lab](https://github.com/dlmastery/simple-coding-harness/blob/main/10_research_studio/01_budget_rsi_scoring/step_01_run_demo/README.md) · Group 01 *Budget RSI* (arXiv:2610.29121) · **headline method 1** ·
run: `python labs/10_03_run_budget_rsi/lab.py` (~40 s)

**Goal.** Run the mechanism end to end on our problem and watch each piece work: scaffold edits → linear readout → HGM search that
evaluates only the top-scored child → comparison with the paper's two controls → cost.

## Code walkthrough
| Step | Code | What happens |
|---|---|---|
| 0 | `SEED_PROGRAM.source` ([`program.py`](../../signalforge/program.py) `render`) | prints the fixed-time controller the improver starts from (31/100 held-out) |
| 1 | `budget_rsi.collect_scaffold_edits` | 12 parents (snapshots of a cheap hill-climb on the 16-instance **fit** split) × 8 random edits = **96 labelled edits**. Each child's fit solve rate is its label. Cost is charged as `readout-labels`. |
| 2 | `train_readout` → `LinearReadout.fit` → `stats.ridge` | ridge least squares on `[1, parent_rate, 8 diff coordinates]`. The coordinates come from `diff_features.diff_features(parent_src, child_src)`: unified diff + `ast`, nothing executed |
| 3 | slow-motion expansion | one parent proposes 8 children; the readout scores them; *for teaching only* we also run all 8 to show how good the ranking is. The real method runs only the top one. Its diff is printed: that is everything the scorer saw. |
| 4 | `budget_rsi.search(..., mode)` | 40 expansions with `readout` (Budget RSI), `parent_rate` (paper's ablation: the readout sees only the parent's rate, so siblings tie) and `random` (uniform parent, random child), 8 seeds. Parent choice = `_thompson` (Beta(1+solved, 1+failed) draw per evaluated node). Returned program = earliest node with maximal steering count (the paper's rule). |
| 5 | ledger arithmetic | evaluating every proposed child vs expanding only the top one, *including* the readout's own label cost |

## What it shows
* The readout **ranks the slow-motion siblings well**: its top pick was the truly best child, and the worst-scored was near the bottom.
* Over 8 seeds, Budget RSI > parent-rate ablation > random, by +2.9 and +4.4 instances. That is the paper's ordering, with similar
  noise (sd ≈ 11). One lucky seed (97) shows how a headline could overstate the effect (lab 10.01).
* Cost: 78% fewer instance-simulations than evaluating all candidates, after charging the 1,472 label simulations.

## Quiz
**Q1. Purpose of the steering split?** Selection uses steering counts; labels use the separate fit split; the 100 held-out instances are never
touched until the end. **Q2. Why synthetic edits?** Ours are not synthetic numbers. They are real source diffs of real programs, generated by
operators instead of GPT-4o. **Check-your-understanding 2 and 3** (fewer features, fewer edits) are answered with measurements in 10.04.
